# 記事UI案 — 初見読者を固有名詞で置いていかない

## 方針

**人物・用語を押すと右側にTipsが出る**構成を採用候補とする。

PC：
- 本文 左 70〜75%
- Tips 右 25〜30%
- Tipsはsticky
- 名前を押すと内容が切り替わる

スマホ：
- 名前タップでモーダル / ボトムシート
- 本文を離脱せず説明を見られる

## Tipsの情報量
1項目 80〜180字程度。

表示：
- 名前
- 初登場作品
- その時の立場
- なぜ今の記事で重要か
- ネタバレ強度（必要なら）

### 例

**大神美智男**  
初登場：『4』  
大神博之の父として登場する大資本家。当初は「とんでもなく金持ちな父」に見えるが、後のオオガミ・6人組を語る中心人物になる。

## 差別化としての価値

パワポケ記事の最大の問題は、**固有名詞を説明するとテンポが死に、説明しないと初見が死ぬ**こと。

Tipsを別レイヤーにすることで、
- 既プレイヤーはテンポよく読む
- 初見は必要な人物だけ補足を開く
- 本文を人物辞典化しすぎない

という両立ができる。

# Web Design Director準拠の実装制約

## Central concept

> **インディーゲーム雑誌の長文特集 × ファン研究資料庫**

右側Tipsは「SaaSの補助カード」ではなく、雑誌の欄外注釈・人物索引・資料カードのように見せる。

## 長文可読性
- 本文幅は日本語35〜45字/行程度を基準。
- line-height 1.7〜2.0。
- PCでも本文を横に広げすぎない。

## Accessibility
- Tips triggerはbuttonまたは同等にkeyboard操作可能なnative要素を使用。
- visible focusを付ける。
- mobile modalはEscapeで閉じられ、focusを開いた元へ戻す。
- touch targetは44px程度以上。
- reduced motion設定時はtransition/animationを止めるか最小化。

## QA
- 320 / 768 / wide desktopで確認。
- skip linkを実装。
- sticky Tipsとanchor scrollが干渉しないようscroll offsetを定義。
- horizontal overflow、長い人物名、長い見出しを確認。
