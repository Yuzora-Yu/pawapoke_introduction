# 記事UI案 — 初見読者を固有名詞で置いていかない

## 方針

**人物・用語を押すと右側にTipsが出る**構成を採用候補とする。

PC：
- 本文 左 70〜75%
- Tips 右 25〜30%
- Tipsはsticky
- 名前を押すと内容が切り替わる

スマホ：
- 名前タップでモーダル / ボトムシート
- 本文を離脱せず説明を見られる

## Tipsの情報量
1項目 80〜180字程度。

表示：
- 名前
- 初登場作品
- その時の立場
- なぜ今の記事で重要か
- ネタバレ強度（必要なら）

### 例

**大神美智男**  
初登場：『4』  
大神博之の父として登場する大資本家。当初は「とんでもなく金持ちな父」に見えるが、後のオオガミ・6人組を語る中心人物になる。

## 差別化としての価値

パワポケ記事の最大の問題は、**固有名詞を説明するとテンポが死に、説明しないと初見が死ぬ**こと。

Tipsを別レイヤーにすることで、
- 既プレイヤーはテンポよく読む
- 初見は必要な人物だけ補足を開く
- 本文を人物辞典化しすぎない

という両立ができる。



## Tipsのカテゴリを人物以外へ拡張

本文の固有名詞負荷を下げるため、Tipsは人物辞典だけにしない。

- `character`：人物
- `organization`：組織・企業
- `technology`：技術・物質
- `power`：能力分類
- `concept`：計画・世界史用語
- `place`：舞台・施設
- `ura`：裏サクセス名
- `meta`：リセット座談会などゲーム外縁の用語

2026-09-05時点で `data/tips.json` は65語まで拡張。
記事本文に出ない語を無理に表示する必要はなく、詳細記事へ展開する際の共通辞書として持つ。
